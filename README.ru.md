# Flowwit

[English version](README.md)

Мультиагентная LLM-платформа с визуальным движком воркфлоу. Можно общаться с агентами напрямую в чате, а можно строить детерминированные пайплайны (граф нод), которые агенты исполняют пошагово — вместо того чтобы каждый раз полагаться на решение LLM, что делать дальше.

Это бэкенд платформы. Есть отдельный фронтенд с визуальным редактором воркфлоу — опциональный, работать можно и без него, например через Telegram-канал.

## Установка

```bash
git clone https://github.com/Kirilqa/flowwit-backend
cd flowwit-backend
npm install
```

## Настройка

Скопировать файл-пример окружения и задать хотя бы один ключ провайдера:

```bash
cp .env.example .env
```

```env
OPENAI_API_KEY=sk-...
# или
OPENROUTER_API_KEY=sk-or-...
```

Обязателен хотя бы один из `OPENAI_API_KEY` / `OPENROUTER_API_KEY` — регистрируется только тот провайдер, чей ключ задан. Всё остальное в `.env.example` (порт/host сервера, пути хранения, доп. опции провайдеров, настройки каналов) — опционально, с разумными дефолтами.

Все персистентные данные (конфиги агентов/MCP/каналов, сессии, скиллы, память, воркфлоу, запланированные задачи) по умолчанию лежат под `./data/` — для сохранности достаточно бэкапить или монтировать эту одну папку. При первом запуске (пустая `./data/`) сервер сам создаёт стартового агента и устанавливает пять системных скиллов-гайдов — руками ничего заводить не нужно.

## Запуск

```bash
npm run dev             # API-сервер на http://localhost:3000 (или SERVER_PORT), с hot reload конфигов
npm run dev -- --chat   # консольный чат вместо сервера
```

Для продакшн-сборки:

```bash
npm run build
npm run start
```

Или через Docker:

```bash
docker build -t flowwit-backend .
docker run --env-file .env -p 3000:3000 -v $(pwd)/data:/app/data flowwit-backend
```

Монтирование `-v` — это то, что позволяет данным пережить пересоздание контейнера (например, на следующем `docker run` после обновления) — без него всё под `./data/` живёт только в writable-слое контейнера и теряется в момент его удаления.

## Использование

- **Серверный режим** (по умолчанию) — REST + SSE API для чата, воркфлоу, агентов, планировщика и остального. SSE-стрим генерации — `POST /messages`.
- **Консольный режим** (`--chat`) — общение с агентом прямо в терминале.
- Агенты, MCP-серверы, каналы, воркфлоу и запланированные задачи описываются декларативно в JSON-файлах (по умолчанию `./data/agents.json`, `./data/mcp.json`, `./data/channels.json`, `./data/workflows/`, `./data/scheduled-tasks.json` — пути настраиваются, см. `.env.example`) и подхватываются на лету без рестарта процесса.

## Что внутри

- **Агенты** — LLM-агенты с вызовом инструментов, две стратегии мышления (свободный ReAct и явный Plan-and-Execute), скиллы, сабагенты, MCP-серверы, бюджеты, гуардрейлы с интерактивным подтверждением, персистентные сессии.
- **Скиллы** — файловые `SKILL.md` с инструкциями, скриптами (исполняются, не читаются как код) и бинарными ассетами; маркетплейс ClawHub для установки/обновления чужих скиллов.
- **WorkFlow** — бэкенд для графового редактора: типизированные порты, параллельные ветки, циклы, стриминг событий выполнения.
- **Scheduler** — запуск промпта агента или воркфлоу разово, по cron-расписанию или по требованию.
- **Каналы** — Web (SSE) и Console из коробки, Telegram как первый пользовательский канал; у каждого свои настройки и hot reload.
- **Гуардрейлы** — интерактивное разрешение/запрет вызовов инструментов, с правилами на трёх уровнях (global/agent/session) и glob-паттернами.
- **Память** — файловая персистентная память агента между сессиями, с настраиваемыми лимитами по объёму.
